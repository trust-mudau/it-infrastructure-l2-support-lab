# Onboarding, Offboarding and Access SOP

**Status:** synthetic process design aligned to Tier 1 / IAM support. The separate IAM lab contains deeper lifecycle workflow design; live tenant execution is not claimed.

## Joiner

- Validate approved starter request, manager, start date, department and role.
- Check for duplicate/existing identity before creating anything.
- Create or request creation of the user account using approved naming standards.
- Assign only baseline groups/licences required for the role.
- Record manager/application-owner approvals for non-baseline access.
- Prepare or assign the end-user device and update the asset register.
- Confirm MFA/security-registration requirements are communicated.
- Verify sign-in, required application access and device assignment.
- Record completion evidence and close against SLA.

## Mover

- Capture existing access before change.
- Remove role/department access no longer justified.
- Update attributes and add only newly approved access.
- Specifically check for residual access and privilege accumulation.
- Update asset records if device ownership/location changes.
- Verify the new access state and record evidence.

## Leaver

- Validate termination request and effective time.
- Disable/sign-out account according to approved process.
- Remove/revoke access and group memberships according to policy.
- Recover assigned equipment and update asset status.
- Preserve business data/ownership according to retention policy.
- Verify access is no longer active.
- Record who approved, who executed, what changed and when.

## Access request rule

No access is granted solely because a user asks for it. Confirm business purpose and required approval, apply least privilege, verify the result, and keep an auditable record.
